[![Обновление расписания](https://github.com/zxkittenxd/barsu-schedule/actions/workflows/update-schedule.yml/badge.svg?branch=main)](https://github.com/zxkittenxd/barsu-schedule/actions/workflows/update-schedule.yml)
[![Сайт](https://img.shields.io/badge/сайт-открыть-2ea44f?logo=github)](https://zxkittenxd.github.io/barsu-schedule/)
[![Стек](https://img.shields.io/badge/стек-vanilla%20JS%20%2B%20Python-3776ab)](#стек)

Расписание занятий **всех групп и преподавателей** Барановичского государственного университета — на одном статическом сайте. Неделя ПН–СБ, отметка «идёт сейчас», замены, поиск и ссылки на конкретный день. Без бэкенда и без сборки: данные собирает Python-скрипт с официального [rasp.barsu.by](https://rasp.barsu.by/stud.php), свежий снимок публикует GitHub Actions.

**🔗 Сайт: https://zxkittenxd.github.io/barsu-schedule/**

> **Про старые адреса.** Репозиторий раньше назывался `pitt21-barsu-schedule`. Под этим именем остался отдельный репозиторий-архив: его Pages и зеркало `pitt21-rasp.surge.sh` отвечают, но отдают замороженную сборку от 05.11.2026 — без режима преподавателей, автообновления и живого времени. Актуальна только ссылка выше.

Актуальное число групп и преподавателей, недели и время сбора снимка — в [`data/version.json`](data/version.json) (`groups`, `teachers`, `currentWeek`, `fetchedAt`). Счётчики меняются вместе с каталогом университета и не захардкожены ни в коде, ни в этом файле.

Неофициальный студенческий проект.

## Возможности

**Навигация**
- Два режима — «Группы» и «Преподаватели»: переключатель в шапке, свои hash-адреса, последний выбор запоминается.
- Все группы и преподаватели вуза; списки строятся из каталога университета автоматически и группируются по факультетам (группы) и кафедрам (преподаватели).
- Модалка выбора с поиском: понимает дефисы и пробелы (`ПИТТ-21` = `ПИТТ21`), ищет по коду и специальности, у преподавателей — по ФИО.
- Сквозные переходы: клик по группе в расписании преподавателя открывает расписание группы, клик по ФИО в расписании группы — расписание преподавателя.
- Меню недель с пометками «есть данные / нет данных / не опубликовано»; сегмент-контрол дней ПН–СБ можно перетаскивать пальцем.

**Время и данные**
- «Идёт сейчас» на текущей паре по времени Минска; карточка «следующая пара» с обратным отсчётом и подсказкой про перемену.
- Автообновление в открытой вкладке: раз в 5 минут и при возврате на страницу клиент сверяет `data/version.json` и подхватывает новый снимок без перезагрузки; кнопка «обновить» делает то же вручную.
- Официальный фрейм `rasp.barsu.by` как эталон «как есть» (в режиме преподавателей форма уходит в `teach.php`), грузится лениво.
- Кэш просмотренных расписаний в `localStorage` (`bargu_*`) — они открываются без сети.

**Оформление**
- Темы `material-dark` (по умолчанию) и `material-light`, акцентные цвета, стеклянные слои и `backdrop-filter`.
- `prefers-reduced-motion`, компактный мобильный топбар, модалка выбора почти на всю высоту экрана.

## Как это работает

```
rasp.barsu.by ──(Python, stdlib)──▶ data/*.json + BOOT-снимок в index.html
      ▲                                        │
      │ cron каждые 3 ч                        ▼
GitHub Actions ──смоук-тест──▶ коммит в main ──▶ GitHub Pages
                                               │
                    браузер ◀──version.json───┘ (опрос раз в 5 мин)
```

1. **Сбор.** `tools/scrape.py` делает GET `stud.php` (каталог групп, список недель), затем POST по каждой группе и неделе и разбирает HTML-таблицы. Тянутся текущая и две следующие недели (там появляются замены) плюс незаполненные недели за последние 21 день. Пустые прошлые недели запоминаются в `meta.probed` и больше не запрашиваются — университет их уже не правит.
2. **Преподаватели.** Каталог имён и кафедр — один GET `teach.php`. Текущая неделя преподавателя берётся напрямую из `teach.php` (его таблица богаче групповой), остальные недели строятся транспозицией уже собранных данных групп — без лишних запросов к университету; выборочная сверка с официальным `teach.php` расхождений не показала.
3. **Публикация.** Результат пишется в `data/gNNN.json`, `data/pNNN.json`, `data/teachers.json`, `data/version.json` и в BOOT-снимок внутри `index.html`. Файл перезаписывается, только если содержимое реально изменилось: нет изменений — нет коммита и пересборки Pages.
4. **Мгновенный старт.** В `index.html` встроен JSON с каталогом групп, списком недель и расписанием группы по умолчанию (ПИТТ21) — страница рисуется сразу и без сети. Остальное подгружается по требованию; каталог преподавателей — при первом входе в режим.
5. **Клиент.** «Обновить» перечитывает `version.json` и JSON текущей сущности с того же домена. Изменилось число групп или преподавателей — страница перезагружается, иначе данные обновляются на месте.

> **Почему сбор на сервере, а не в браузере.** `rasp.barsu.by` не отдаёт CORS-заголовки и принимает параметры только в POST, поэтому напрямую из браузера к нему не обратиться. Публичные CORS-реле не подошли: allorigins и codetabs не пробрасывают POST-тело, corsproxy.io требует ключ (401), cors.lol отдаёт 429, corsfix — 403. GitHub Actions решает задачу надёжно и без сторонних сервисов.

## Структура репозитория

```
├── index.html                  # всё приложение: CSS + разметка + JS + BOOT-снимок данных
├── README.md
├── data/
│   ├── gNNN.json               # расписание группы (грузятся лениво)
│   ├── pNNN.json               # расписание преподавателя (грузятся лениво)
│   ├── teachers.json           # каталог: преподаватель → кафедра → файл
│   └── version.json            # метка свежести снимка, её опрашивает клиент
├── tools/
│   ├── scrape.py               # сбор rasp.barsu.by → data/*.json + BOOT (только stdlib)
│   └── smoke-test.js           # рендер-тест страницы в jsdom
└── .github/workflows/
    └── update-schedule.yml     # cron: собрать → проверить → закоммитить
```

## Форматы данных

| Файл | Что внутри |
|---|---|
| `data/gNNN.json` | расписание группы: `meta` + `schedules` по неделям (пример ниже) |
| `data/pNNN.json` | расписание преподавателя: та же структура, но вместо `teacher` у занятия перечислены `groups` |
| `data/teachers.json` | `kafedras` (список кафедр) и `teachers` (`name`, `kafedra`, `file`, `has`, `weeks`) |
| `data/version.json` | `fetchedAt`, `currentWeek`, `groups`, `teachers`, `publishedWeeks`, `publishedWeeksTeachers` — метка свежести для клиента |

```jsonc
// data/gNNN.json (сокращённо)
{
  "meta": {
    "group": "ПИТТ21",
    "faculty": "Инженерный факультет",
    "speciality": "Производство изделий на основе трехмерных технологий",
    "source": "https://rasp.barsu.by/stud.php",
    "fetchedAt": "…",
    "weeksAvailable": ["2026-11-30", "2026-11-23", "…"],
    "currentWeek": "2026-11-23",
    "probed": ["2026-11-16", "…"]          // недели с пустым ответом — не перезапрашиваются
  },
  "schedules": {
    "2026-11-23": {
      "weekBegin": "2026-11-23",
      "heading": "Расписание  на неделю c 23.11.26",
      "lastUpdate": "…",                    // отметка обновления самого университета
      "days": [{
        "abbr": "ПН", "name": "Понедельник",
        "date": "23.11", "iso": "2026-11-23", "dateFull": "23.11.2026",
        "slots": [{
          "n": 1, "time": "8:00–9:25",
          "lessons": [{
            "subjectRaw": "ИнострЯзык", "type": "ПЗ",
            "teacher": "Любанец И.И.",
            "room": "1/105", "building": "Парк",
            "subgroup": "2", "note": "Нем",
            "replacement": false
          }]
        }]
      }]
    }
  }
}
```

Поля занятия: `subjectRaw` — предмет как на сайте университета; `type` — `ЛК` (лекция), `ПЗ` (практика), `ЛЗ` (лабораторная), `СЗ` (семинар), встречаются также `ЭКЗ`, `ЗАЧ`, `КП`, `КР`, `КН`; `teacher` (у групп) или `groups` (у преподавателей); `room`, `building`; `subgroup`; `note` (подгруппа, язык, уточнение); `replacement` — пара стоит вместо другой, то есть замена.

## Hash-ссылки

Формат `#<группа>/<неделя>/<день>` и `#t/<Фамилия И.О.>/<неделя>/<день>`; неделя — ISO-дата понедельника:

- `#ПИТТ21/2026-11-16/ПН` — расписание группы;
- `#t/Александренок М.С./2026-11-16/ПН` — расписание преподавателя.

Ссылкой можно поделиться: при открытии состояние восстанавливается.

## Локальный запуск

`fetch()` не работает с `file://`, поэтому нужен статический сервер:

```bash
git clone https://github.com/zxkittenxd/barsu-schedule.git
cd barsu-schedule
python3 -m http.server 8080     # открыть http://localhost:8080
```

Пересобрать данные самому (Python 3.12, только стандартная библиотека):

```bash
python3 tools/scrape.py --dry-run            # отчёт без записи файлов
python3 tools/scrape.py                      # обновить data/*.json и BOOT-снимок
python3 tools/scrape.py --only ПИТТ21        # одна группа (отладка)
```

| Флаг | Смысл (значение по умолчанию) |
|---|---|
| `--workers N` | параллельных запросов (4) |
| `--timeout N` | таймаут запроса в секундах (30) |
| `--max-weeks N` | максимум недель на группу (8) |
| `--forward-weeks N` | сколько недель вперёд от текущей обновлять всегда (2) |
| `--backfill-days N` | насколько назад добирать незаполненные недели (21) |
| `--refetch-all` | разово перетянуть все недели, игнорируя `probed` |
| `--only КОД` | собрать только указанную группу |
| `--dry-run` | ничего не записывать |
| `--root DIR` | корень репозитория (текущий каталог) |
| `--report FILE` | отчёт для текста коммита |

Рендер-тест (Node.js + jsdom, нужен запущенный локальный сервер):

```bash
python3 -m http.server 8099 &
npm install --no-save --prefix /tmp/jsdom jsdom
NODE_PATH=/tmp/jsdom/node_modules node tools/smoke-test.js
# против опубликованного сайта:
NODE_PATH=/tmp/jsdom/node_modules node tools/smoke-test.js https://zxkittenxd.github.io/barsu-schedule/
```

В тесте нет захардкоженных чисел групп и дат — ожидания читаются из `data/version.json`, поэтому проверяется согласованность «страница == данные», и новые группы тест не роняют.

## Деплой и автообновление

Сайт публикуется через **GitHub Pages** (ветка `main`, корень репозитория): каждый пуш пересобирает https://zxkittenxd.github.io/barsu-schedule/. Отдельной сборки нет — Pages отдаёт файлы как есть.

Workflow **«Обновление расписания»** (`.github/workflows/update-schedule.yml`):

- **когда** — cron `10 */3 * * *` (UTC; Минск = UTC+3), кнопка *Run workflow* и самопроверка при изменениях `tools/scrape.py` или самого workflow;
- **что делает** — собирает данные → прогоняет рендер-тест в jsdom → коммитит в `main` от `github-actions[bot]` → Pages пересобирается;
- **если источник недоступен или сменил вёрстку** — скрипт падает, данные не трогает, workflow краснеет (GitHub пришлёт письмо), сайт продолжает показывать последний рабочий снимок;
- **если изменений нет** — коммита и пересборки не будет.

> **Cron на GitHub — не точный таймер.** Запуски приходят с задержкой, часть пропускается: по последним запускам интервал составляет примерно 8–12 часов, с перерывами до 14 (все успешные). Время последнего запуска видно на вкладке *Actions*; `fetchedAt` в `data/version.json` сдвигается, только когда сбор принёс изменения.
>
> GitHub отключает cron-воркфлоу в репозиториях без активности 60 дней. Если обновления встали — запустите *Run workflow* вручную, это вернёт планировщик к жизни.

## Ограничения

- **Только публичные данные.** Всё берётся из открытых `rasp.barsu.by` (`stud.php`, `teach.php`); токены и секреты в репозитории не хранятся.
- **Парсер завязан на разметку университета.** Изменение вёрстки на стороне БарГУ сломает сбор: workflow упадёт, а сайт продолжит показывать последний рабочий снимок.
- **Прошлые недели не перепроверяются** (университет их уже не правит) — в старых неделях возможны исторические данные.
- **Часть преподавателей без кафедры** (пустой `kafedra` в `data/teachers.json`): они находятся поиском и имеют расписание, но не попадают в группировку по кафедрам.
- **Модалка выбора** ограничена по высоте в `vh` (единицы большого вьюпорта): на телефонах с динамическими панелями браузера (iOS Safari) низ карточки может уходить под панель — тогда прокручивается подложка. Переход на `dvh`/`svh` — в планах.
- **Старые зеркала заморожены** — см. блок «Про старые адреса» в начале.

## Стек

Один `index.html`: HTML + CSS (переменные тем, стеклянные слои, `backdrop-filter`, keyframes) + vanilla JS без зависимостей и сборщика. Инструменты: Python 3.12 (только stdlib) для сбора данных, Node.js + jsdom для рендер-теста.
