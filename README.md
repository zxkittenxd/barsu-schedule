Расписание занятий **всех групп и преподавателей** Барановичского государственного университета (БарГУ) — один статический сайт с данными с официального [rasp.barsu.by](https://rasp.barsu.by/stud.php).

**🔗 Сайт: https://zxkittenxd.github.io/barsu-schedule/**

> **Про старые адреса.** Репозиторий раньше назывался `pitt21-barsu-schedule`, и под этим именем остался отдельный репозиторий: его Pages и зеркало `pitt21-rasp.surge.sh` живы, но оба отдают архивную сборку (153 КБ, снимок от 06.10.2026 — без режима преподавателей, автообновления и живого времени). Актуален только сайт на GitHub Pages, ссылка выше.

Неофициальный студенческий проект. Ни бэкенда, ни сборки: только HTML/CSS/JS, а свежее расписание собирает GitHub Actions.

**157 групп · 254 преподавателя · 5 факультетов · 15 кафедр** — точные числа и свежесть снимка смотрите в [`data/version.json`](data/version.json) (поля `groups`, `teachers`, `fetchedAt`); сбор данных запускается автоматически несколько раз в сутки.

## Возможности

- **Все группы и преподаватели вуза** — на момент последней сборки 157 групп на 5 факультетах (инженерный, экономики и права, педагогики и психологии, лингвистический, ИПКиП) и 254 преподавателя на 15 кафедрах. Списки и счётчики формируются автоматически из каталога университета, поэтому растут без правок кода.
- **Два режима** — «Группы» и «Преподаватели»: сегмент-переключатель `#modeSeg`, пункт в меню, отдельные hash-ссылки.
- **Быстрый выбор** — модалка с поиском, который понимает дефисы и пробелы (`ПИТТ-21` = `ПИТТ21`) и ищет по специальности (в режиме преподавателей — по ФИО); вкладки факультетов и кафедр.
- **Сквозная навигация** — в расписании преподавателя клик по группе открывает её расписание, в расписании группы клик по ФИО — расписание преподавателя.
- **Неделя ПН–СБ** — меню недель с пометкой «есть / нет данных / не опубликовано», переключение дней сегмент-контролом, в том числе перетаскиванием пальцем.
- **Живое время** — отметка «идёт сейчас» на текущей паре (по времени Минска) и карточка «следующая пара» с обратным отсчётом до начала и подсказкой про перемену.
- **Автообновление** — открытая вкладка раз в 5 минут и при возврате на страницу проверяет `data/version.json` и подхватывает новый снимок без перезагрузки; кнопка «обновить» работает вручную.
- **Официальный фрейм** с rasp.barsu.by — эталон «как есть» (в режиме преподавателей форма уходит в `teach.php`), загружается лениво.
- **Оформление** — темы `material-dark` / `material-light` (переключатель в шапке), акцентные цвета, поддержка `prefers-reduced-motion`, компактный мобильный топбар и модалка выбора почти на всю высоту экрана.
- **Офлайн-кэш** в `localStorage` (ключи с префиксом `bargu_`) — просмотренные расписания открываются даже без сети.

## Структура репозитория

```
├── index.html                  # всё приложение (CSS + разметка + JS) и BOOT-снимок данных
├── README.md                   # этот файл
├── data/
│   ├── g000.json …             # по файлу на группу, грузятся лениво
│   ├── p000.json …             # по файлу на преподавателя
│   ├── teachers.json           # каталог: преподаватель → кафедра → имя файла
│   └── version.json            # метка свежести: по ней вкладка понимает, что вышел новый снимок
├── tools/
│   ├── scrape.py               # сбор rasp.barsu.by → data/*.json + BOOT (только stdlib Python)
│   └── smoke-test.js           # рендер-тест страницы в jsdom перед публикацией
└── .github/workflows/
    └── update-schedule.yml     # cron: собрать → проверить → закоммитить
```

## Как работают данные

1. **Группы.** `tools/scrape.py` делает GET `stud.php` (каталог групп и список недель), затем POST по каждой группе и неделе и парсит HTML-таблицы. Тянутся текущая и две следующие недели (там появляются замены) плюс незаполненные недели за последние 21 день. Прошлые недели университет уже не правит, поэтому пустой ответ запоминается в `meta.probed` и повторно не запрашивается.
2. **Преподаватели.** Каталог имён и кафедр берётся из `teach.php` одним GET. Текущая неделя преподавателя запрашивается напрямую из `teach.php` — его таблица богаче групповой. Остальные недели строятся транспозицией уже собранных данных групп (в каждой паре группы указан преподаватель), поэтому дополнительных запросов к университету не нужно. Выборочная сверка с официальным `teach.php` дала полное совпадение пар.
3. **Публикация.** Результат пишется в `data/gNNN.json`, `data/pNNN.json`, `data/teachers.json`, в BOOT-снимок внутри `index.html` и в `data/version.json`. Файл перезаписывается только если содержимое реально изменилось — без изменений коммита и пересборки Pages не будет.
4. **Снимок.** В `index.html` встроен JSON: каталог всех групп, `weeksAvailable` и расписание группы по умолчанию (ПИТТ21). Остальное подгружается по требованию, каталог преподавателей — лениво при первом открытии режима.
5. **Клиент.** Кнопка «обновить» перечитывает `version.json` и JSON текущей сущности с того же домена — это работает всегда и мгновенно. Раз в 5 минут (`setInterval(checkForUpdate, 5*60*1000)`) и при возврате на вкладку сайт сам проверяет версию. Если изменилось число групп/преподавателей — страница перезагружается, иначе данные обновляются на месте.
6. **Форматы.** `data/gNNN.json` — `meta` (группа, факультет, специальность, `fetchedAt`, доступные недели, `probed`) + `schedules` (неделя → день → пара → занятия с типом, преподавателем, аудиторией, подгруппой). `data/pNNN.json` — то же, но вместо преподавателя в занятии указаны группы.

> **Почему сбор на сервере, а не запрос из браузера.** `rasp.barsu.by` не отдаёт CORS-заголовки и принимает параметры только в POST, поэтому браузер не может обратиться к нему напрямую. Публичные CORS-реле не подошли: allorigins и codetabs не пробрасывают POST-тело, corsproxy.io требует ключ (401), cors.lol отдаёт 429, corsfix — 403. Сбор в GitHub Actions решает задачу надёжно и без сторонних сервисов.

## Форматы данных

`data/gNNN.json` — расписание группы:

```jsonc
{
  "meta": {
    "group": "ПИТТ21",
    "faculty": "Инженерный факультет",
    "speciality": "Производство изделий на основе трехмерных технологий",
    "source": "https://rasp.barsu.by/stud.php",
    "fetchedAt": "2026-11-23 15:23:18",
    "weeksAvailable": ["2026-11-30", "2026-11-23", "..."],
    "currentWeek": "2026-11-23",
    "probed": ["2026-11-16", "..."]
  },
  "schedules": {
    "2026-11-23": {
      "weekBegin": "2026-11-23",
      "heading": "Расписание  на неделю c 23.11.26",
      "lastUpdate": "2026-11-20 11:02:35",
      "days": [{
        "abbr": "ПН", "name": "Понедельник",
        "date": "23.11", "iso": "2026-11-23", "dateFull": "23.11.2026",
        "slots": [{
          "n": 1, "time": "8:00–9:25",
          "lessons": [{
            "subjectRaw": "ИнострЯзык", "type": "ПЗ",
            "teacher": "Любанец И.И.",
            "room": "1/105", "building": "Парк",
            "subgroup": "2", "note": "Нем",
            "replacement": false
          }]
        }]
      }]
    }
  }
}
```

- `data/pNNN.json` — расписание преподавателя: та же структура, но вместо `teacher` в занятии перечислены `groups`.
- `data/teachers.json` — каталог: `kafedras` (список кафедр) и `teachers` (`name`, `kafedra`, `file`, `has`, `weeks`).
- `data/version.json` — метка свежести: `fetchedAt`, `currentWeek`, `groups`, `teachers`, `publishedWeeks`, `publishedWeeksTeachers`. Именно этот файл клиент опрашивает, чтобы понять, что появился новый снимок.

Поля внутри занятия: `subjectRaw` (предмет как на сайте университета), `type` (чаще всего `ЛК` — лекция, `ПЗ` — практика, `ЛЗ` — лабораторная, `СЗ` — семинар; встречаются также `ЭКЗ`, `ЗАЧ`, `КП`, `КР`, `КН`), `teacher` или `groups`, `room`, `building`, `subgroup`, `note` (примечание — подгруппа, язык, уточнение), `replacement` (пара стоит вместо другой, то есть замена).

## Hash-ссылки

Формат: `#<группа>/<неделя>/<день>` и `#t/<Фамилия И.О.>/<неделя>/<день>`, например:

- `#ПИТТ21/2026-11-16/ПН` — расписание группы
- `#t/Александренок М.С./2026-11-16/ПН` — расписание преподавателя

Неделя — ISO-дата понедельника. Ссылкой можно поделиться: состояние восстанавливается при открытии.

## Локальный запуск

`fetch()` не работает с `file://`, поэтому нужен любой статический сервер:

```bash
git clone https://github.com/zxkittenxd/barsu-schedule.git
cd barsu-schedule
python3 -m http.server 8080
# открыть http://localhost:8080
```

Ручной прогон сборщика (Python 3.12, только стандартная библиотека):

```bash
python3 tools/scrape.py --dry-run          # отчёт без записи файлов
python3 tools/scrape.py                    # пересобрать data/*.json и BOOT-снимок
python3 tools/scrape.py --only ПИТТ21      # одна группа (отладка)
python3 tools/scrape.py --workers 4 --report report.txt
```

Полезные флаги (в скобках — значения по умолчанию): `--workers N` (4, параллельные запросы), `--timeout N` (30 с), `--max-weeks N` (8), `--forward-weeks N` (2), `--backfill-days N` (21), `--refetch-all` (игнорировать `meta.probed`), `--root DIR` (корень репозитория), `--report FILE` (отчёт для текста коммита).

Рендер-тест (нужны Node.js и запущенный локальный сервер):

```bash
python3 -m http.server 8099 &
npm install --no-save --prefix /tmp/jsdom jsdom
NODE_PATH=/tmp/jsdom/node_modules node tools/smoke-test.js
# или против опубликованного сайта:
NODE_PATH=/tmp/jsdom/node_modules node tools/smoke-test.js https://zxkittenxd.github.io/barsu-schedule/
```

Тест не содержит захардкоженных чисел групп и дат: ожидания читаются из `data/version.json`, поэтому проверяется согласованность «страница == данные», и добавление новых групп тест не роняет.

## Деплой и автообновление

Сайт публикуется через **GitHub Pages** (ветка `main`, корень репозитория): каждый пуш в `main` пересобирает https://zxkittenxd.github.io/barsu-schedule/. Дополнительной сборки нет — Pages отдаёт файлы как есть.

Workflow **«Обновление расписания»** (`.github/workflows/update-schedule.yml`):

- **когда:** cron `10 */3 * * *` (UTC, Минск = UTC+3) — по плану каждые 3 часа, фактически реже (см. примечание ниже); плюс кнопка *Run workflow* и самопроверка при изменениях `tools/scrape.py` или самого workflow;
- **что делает:** собирает данные → прогоняет рендер-тест в jsdom → коммитит в `main` от `github-actions[bot]` → Pages пересобирается;
- **если источник недоступен** или сменил вёрстку: скрипт падает, данные не трогает, workflow краснеет (GitHub пришлёт письмо), сайт продолжает показывать последний рабочий снимок;
- **если изменений нет** — коммита и пересборки не будет.

> Cron на GitHub — не точный таймер: запуски по расписанию приходят с задержкой, а часть пропускается. У этого workflow с 12.10 по 24.11.2026 состоялось меньше половины запланированных запусков: они шли в среднем раз в 7 часов, с перерывами до 14 часов. Время последнего запуска видно на вкладке *Actions*; `fetchedAt` в `data/version.json` сдвигается, только когда сбор принёс изменения.
>
> GitHub отключает cron-воркфлоу в репозиториях без активности 60 дней. Если обновления встали — запустите *Run workflow* вручную, это вернёт планировщик к жизни.

## Ограничения и нюансы

- **Только публичные данные.** Всё берётся из открытых `rasp.barsu.by` (`stud.php`, `teach.php`), токены и секреты в репозитории не хранятся.
- **Парсер завязан на разметку университета.** Изменение вёрстки на стороне БарГУ может сломать сбор — тогда workflow упадёт, а сайт продолжит показывать последний рабочий снимок.
- **Старые зеркала заморожены.** Прежний адрес `…/pitt21-barsu-schedule/` и `pitt21-rasp.surge.sh` не обновляются: оба отдают архивную сборку (153 КБ со снимком от 06.10.2026, против ~199 КБ у актуального сайта), без режима преподавателей и автообновления. Достоверна только ссылка на GitHub Pages.
- **Прошлые недели не перепроверяются** (университет их уже не правит), поэтому в старых неделях могут остаться исторические данные.
- **У части преподавателей кафедра не определена** (пустое значение `kafedra` в `data/teachers.json`) — они находятся поиском и имеют расписание, но не попадают в группировку по кафедрам.
- **Модалка выбора** ограничена по высоте в `vh` (единицы большого вьюпорта). На телефонах с динамическими панелями браузера (iOS Safari) низ карточки может уходить под панель — тогда прокручивается вся подложка. Переход на `dvh`/`svh` — в планах.

## Стек

Один `index.html`: HTML + CSS (стеклянные слои, `backdrop-filter`, CSS-переменные тем, keyframes) + vanilla JS без зависимостей и сборщика. Инструменты — Python 3.12 (только stdlib) и Node.js + jsdom для теста.
