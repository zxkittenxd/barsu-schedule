# Расписание БарГУ

Сайт расписания занятий **всех групп БарГУ** (Барановичский государственный университет) в стиле **liquid glass**: стеклянные карточки с `backdrop-filter`, анимированный градиентный фон, пружинные анимации, тёмная и светлая темы. Данные подхватываются с официального сайта [rasp.barsu.by](https://rasp.barsu.by).

## Возможности

- **Все группы университета** — 121 группа, 5 факультетов. Выбор группы в модальном окне: вкладки факультетов + поиск по коду и специальности. Поиск нормализован: «ПИТТ-21», «ПИТТ21» и «питт 21» дают одинаковый результат.
- **Выбор недели** — селектор доступных недель из данных расписания.
- **Слайдер дней** в стиле iOS segment control: прозрачный «стеклянный» бегунок, поддержка drag (зажать и перетащить) и кликов.
- **Hash-ссылки** вида `#ГРУППА/НЕДЕЛЯ/ДЕНЬ` — например, `#ПИТТ21/2026-10-05/ВТ`. Можно поделиться ссылкой на конкретный день конкретной группы.
- **Карточка «следующая пара»** с обратным отсчётом.
- **Тёмная и светлая темы**, поддержка `prefers-reduced-motion`, адаптивная мобильная вёрстка.
- **Живое обновление** с rasp.barsu.by (см. ниже) + официальный фрейм университета как запасной вариант.

## Как устроены данные

1. **Снимок (BOOT)** — встроен в `index.html`: список всех групп и полное расписание группы по умолчанию (ПИТТ-21). Сайт работает сразу, без единого сетевого запроса.
2. **Ленивая загрузка** — при выборе группы подгружается её файл `data/gNNN.json` (один файл на группу).
3. **Кэш** — загруженные и обновлённые данные сохраняются в `localStorage` (ключ на группу).
4. **Live-режим** — браузер запрашивает `rasp.barsu.by/stud.php` через цепочку публичных CORS-реле (allorigins → cors.lol → corsproxy.io → corsfix), HTML парсится на клиенте. Прямые запросы блокирует CORS университета, поэтому нужны реле.
5. **Фолбэк** — если реле не ответили, показывается снимок/кэш, а живая таблица университета доступна в официальном iframe внизу страницы (скрытая форма POST → iframe).

Дата снимка данных видна в футере модального окна и в статус-чипе.

## Структура

```
index.html      — весь сайт: стили, разметка, логика (~44 КБ JS), встроенный снимок BOOT
data/g000.json  — расписание одной группы (meta + schedules по неделям)
…
data/g120.json  — всего 121 файл
```

Формат файла группы: `meta` (код, факультет, специальность, доступные недели, дата сбора) и `schedules` (неделя → дни → слоты пар → занятия: предмет, тип, преподаватель, аудитория, корпус, подгруппа, замены).

## Локальный запуск

Сборка не нужна — это чистая статика:

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

> Через `file://` ленивая загрузка групп и live-режим работать не будут (ограничения браузера на fetch) — используйте любой статический сервер.

## Деплой

- **GitHub Pages**: сборка из корня ветки `main`. Любой push в `main` автоматически пересобирает сайт (~40 секунд).
- **Surge**: зеркало деплоится вручную (`surge . pitt21-rasp.surge.sh`), поэтому может отставать от Pages.

## Ограничения

- Публичные CORS-реле нестабильны (rate-limit'ы, простои). При их отказе сайт показывает снимок/кэш — это ожидаемое поведение, а не поломка.
- Парсер завязан на текущую HTML-разметку `rasp.barsu.by`: если университет изменит вёрстку, live-режим потребует починки парсера (iframe-фолбэк продолжит работать).
- Снимок в `data/` собирается вручную; автоматического пересбора по расписанию пока нет — свежие недели появляются через live-режим.
