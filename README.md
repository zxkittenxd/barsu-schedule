Расписание занятий **всех групп и преподавателей** Барановичского государственного университета: два режима, неделя ПН–СБ, замены, отметка «идёт сейчас» и поиск. Один статический сайт без бэкенда — данные берутся с официального [rasp.barsu.by](https://rasp.barsu.by/stud.php), а свежий снимок собирает GitHub Actions.

Неофициальный студенческий проект. Никакой сборки: HTML + CSS + vanilla JS, плюс Python-скрипт для сбора данных.

## Возможности

**Навигация**
- Все группы и преподаватели вуза: 5 факультетов, 15 кафедр; списки строятся из каталога университета автоматически.
- Два режима — «Группы» и «Преподаватели»: переключатель в шапке, отдельный пункт меню, свои hash-адреса.
- Модалка выбора с поиском: понимает дефисы и пробелы (`ПИТТ-21` = `ПИТТ21`), ищет по специальности, а в режиме преподавателей — по ФИО; вкладки факультетов и кафедр.
- Сквозные переходы: из расписания преподавателя клик по группе открывает её расписание, из расписания группы клик по ФИО — расписание преподавателя.
- Неделя ПН–СБ с меню недель (пометки «есть данные / нет данных / не опубликовано») и сегмент-контролом дней, который можно перетаскивать пальцем.

**Данные и время**
- Отметка «идёт сейчас» на текущей паре по времени Минска и карточка «следующая пара» с обратным отсчётом до начала и подсказкой про перемену.
- Автопроверка обновлений: открытая вкладка раз в 5 минут и при возврате на страницу сверяет `data/version.json` и подхватывает новый снимок без перезагрузки; кнопка «обновить» дублирует это вручную.
- Официальный фрейм с `rasp.barsu.by` как эталон «как есть» (в режиме преподавателей форма уходит в `teach.php`), подгружается лениво.
- Офлайн-кэш в `localStorage` (`bargu_*`): просмотренные расписания открываются без сети.

**Оформление**
- Темы `material-dark` (по умолчанию) и `material-light`, акцентные цвета, стеклянные слои и `backdrop-filter`.
- Поддержка `prefers-reduced-motion`, компактный мобильный топбар, модалка выбора почти на всю высоту экрана.

## Структура репозитория

```
├── index.html                  # всё приложение: CSS + разметка + JS + BOOT-снимок данных
├── README.md
├── data/
│   ├── gNNN.json               # расписание группы (грузятся лениво)
│   ├── pNNN.json               # расписание преподавателя (грузятся лениво)
│   ├── teachers.json           # каталог: преподаватель → кафедра → файл
│   └── version.json            # метка свежести снимка, её опрашивает клиент
├── tools/
│   ├── scrape.py               # сбор rasp.barsu.by → data/*.json + BOOT (только stdlib)
│   └── smoke-test.js           # рендер-тест страницы в jsdom
└── .github/workflows/
    └── update-schedule.yml     # cron: собрать → проверить → закоммитить
```

## Как устроены данные

**1. Сбор.** `tools/scrape.py` делает GET `stud.php` (каталог групп и список недель), затем POST по каждой группе и неделе и разбирает HTML-таблицы. Тянутся текущая и две следующие недели (там появляются замены) плюс незаполненные недели за последние 21 день. Прошлые недели университет уже не правит, поэтому пустой ответ запоминается в `meta.probed` и повторно не запрашивается.

**2. Преподаватели.** Каталог имён и кафедр берётся из `teach.php` одним GET. Текущая неделя преподавателя запрашивается напрямую из `teach.php` — его таблица богаче групповой. Остальные недели строятся транспозицией уже собранных данных групп (в каждой паре группы указан преподаватель), так что лишних запросов к университету нет; выборочная сверка с официальным `teach.php` расхождений не показала.

**3. Публикация.** Результат пишется в `data/gNNN.json`, `data/pNNN.json`, `data/teachers.json`, в BOOT-снимок внутри `index.html` и в `data/version.json`. Файл перезаписывается только если содержимое реально изменилось — без изменений не будет ни коммита, ни пересборки Pages.

**4. Снимок.** В `index.html` встроен JSON: каталог всех групп, `weeksAvailable` и расписание группы по умолчанию (ПИТТ21) — страница рисуется мгновенно и без сети. Остальное подгружается по требованию, каталог преподавателей — лениво при первом входе в режим.

**5. Клиент.** Кнопка «обновить» перечитывает `version.json` и JSON текущей сущности с того же домена. Если изменилось число групп или преподавателей — страница перезагружается, иначе данные обновляются на месте.

> **Почему сбор на сервере, а не в браузере.** `rasp.barsu.by` не отдаёт CORS-заголовки и принимает параметры только в POST, поэтому браузер не может обратиться к нему напрямую. Публичные CORS-реле не подошли: allorigins и codetabs не пробрасывают POST-тело, corsproxy.io требует ключ (401), cors.lol отдаёт 429, corsfix — 403. GitHub Actions решает задачу надёжно и без сторонних сервисов.

## Форматы данных

`data/gNNN.json` — расписание группы:

```jsonc
{
  "meta": {
    "group": "ПИТТ21",
    "faculty": "Инженерный факультет",
    "speciality": "Производство изделий на основе трехмерных технологий",
    "source": "https://rasp.barsu.by/stud.php",
    "fetchedAt": "2026-11-23 15:23:18",
    "weeksAvailable": ["2026-11-30", "2026-11-23", "..."],
    "currentWeek": "2026-11-23",
    "probed": ["2026-11-16", "..."]
  },
  "schedules": {
    "2026-11-23": {
      "weekBegin": "2026-11-23",
      "heading": "Расписание  на неделю c 23.11.26",
      "lastUpdate": "2026-11-20 11:02:35",
      "days": [{
        "abbr": "ПН", "name": "Понедельник",
        "date": "23.11", "iso": "2026-11-23", "dateFull": "23.11.2026",
        "slots": [{
          "n": 1, "time": "8:00–9:25",
          "lessons": [{
            "subjectRaw": "ИнострЯзык", "type": "ПЗ",
            "teacher": "Любанец И.И.",
            "room": "1/105", "building": "Парк",
            "subgroup": "2", "note": "Нем",
            "replacement": false
          }]
        }]
      }]
    }
  }
}
```

| Файл | Что внутри |
|---|---|
| `data/gNNN.json` | расписание группы; структура выше |
| `data/pNNN.json` | расписание преподавателя: та же структура, но вместо `teacher` у занятия перечислены `groups` |
| `data/teachers.json` | `kafedras` (список кафедр) и `teachers` (`name`, `kafedra`, `file`, `has`, `weeks`) |
| `data/version.json` | `fetchedAt`, `currentWeek`, `groups`, `teachers`, `publishedWeeks`, `publishedWeeksTeachers` — метка свежести для клиента |

Поля занятия: `subjectRaw` — предмет как на сайте университета; `type` — `ЛК` (лекция), `ПЗ` (практика), `ЛЗ` (лабораторная), `СЗ` (семинар), встречаются также `ЭКЗ`, `ЗАЧ`, `КП`, `КР`, `КН`; `teacher` или `groups`; `room`, `building`; `subgroup`; `note` (подгруппа, язык, уточнение); `replacement` — пара стоит вместо другой, то есть замена.

## Hash-ссылки

Формат `#<группа>/<неделя>/<день>` и `#t/<Фамилия И.О.>/<неделя>/<день>`; неделя — ISO-дата понедельника:

- `#ПИТТ21/2026-11-16/ПН` — расписание группы
- `#t/Александренок М.С./2026-11-16/ПН` — расписание преподавателя

Ссылкой можно поделиться: состояние восстанавливается при открытии.

## Локальный запуск

`fetch()` не работает с `file://`, поэтому нужен статический сервер:

```bash
git clone https://github.com/zxkittenxd/barsu-schedule.git
cd barsu-schedule
python3 -m http.server 8080     # открыть http://localhost:8080
```

Пересобрать данные самому (Python 3.12, только стандартная библиотека):

```bash
python3 tools/scrape.py --dry-run            # отчёт без записи файлов
python3 tools/scrape.py                      # обновить data/*.json и BOOT-снимок
python3 tools/scrape.py --only ПИТТ21        # одна группа (отладка)
python3 tools/scrape.py --workers 4 --report report.txt
```

| Флаг | Смысл (значение по умолчанию) |
|---|---|
| `--workers N` | параллельных запросов (4) |
| `--timeout N` | таймаут запроса в секундах (30) |
| `--max-weeks N` | сколько недель на группу тянуть максимум (8) |
| `--forward-weeks N` | сколько недель вперёд от текущей обновлять всегда (2) |
| `--backfill-days N` | насколько назад добирать незаполненные недели (21) |
| `--refetch-all` | разово перетянуть все недели, игнорируя `probed` |
| `--only КОД` | собрать только указанную группу |
| `--dry-run` | ничего не записывать |
| `--root DIR` | корень репозитория |
| `--report FILE` | отчёт для текста коммита |

Рендер-тест (нужны Node.js и запущенный локальный сервер):

```bash
python3 -m http.server 8099 &
npm install --no-save --prefix /tmp/jsdom jsdom
NODE_PATH=/tmp/jsdom/node_modules node tools/smoke-test.js
# против опубликованного сайта:
NODE_PATH=/tmp/jsdom/node_modules node tools/smoke-test.js https://zxkittenxd.github.io/barsu-schedule/
```

Тест не содержит захардкоженных чисел групп и дат — ожидания читаются из `data/version.json`, поэтому проверяется согласованность «страница == данные», а новые группы тест не роняют.

## Деплой и автообновление

Сайт публикуется через **GitHub Pages** (ветка `main`, корень репозитория): каждый пуш пересобирает https://zxkittenxd.github.io/barsu-schedule/. Отдельной сборки нет — Pages отдаёт файлы как есть.

Workflow **«Обновление расписания»** (`.github/workflows/update-schedule.yml`):

- **когда** — cron `10 */3 * * *` (UTC, Минск = UTC+3), кнопка *Run workflow* и самопроверка при изменениях `tools/scrape.py` или самого workflow;
- **что делает** — собирает данные → прогоняет рендер-тест в jsdom → коммитит в `main` от `github-actions[bot]` → Pages пересобирается;
- **если источник недоступен или сменил вёрстку** — скрипт падает, данные не трогает, workflow краснеет (GitHub пришлёт письмо), сайт продолжает показывать последний рабочий снимок;
- **если изменений нет** — коммита и пересборки не будет.

> Cron на GitHub — не точный таймер: запуски приходят с задержкой, часть пропускается. За период 12.10–24.11.2026 состоялось меньше половины запланированных запусков: в среднем раз в 7 часов, с перерывами до 14 часов. Время последнего запуска видно на вкладке *Actions*; `fetchedAt` в `data/version.json` сдвигается только когда сбор принёс изменения.
>
> GitHub отключает cron-воркфлоу в репозиториях без активности 60 дней. Если обновления встали — запустите *Run workflow* вручную, это вернёт планировщик к жизни.

## Ограничения

- **Только публичные данные.** Всё берётся из открытых `rasp.barsu.by` (`stud.php`, `teach.php`); токены и секреты в репозитории не хранятся.
- **Парсер завязан на разметку университета.** Изменение вёрстки на стороне БарГУ сломает сбор — workflow упадёт, а сайт продолжит показывать последний рабочий снимок.
- **Прошлые недели не перепроверяются** (университет их уже не правит), поэтому в старых неделях возможны исторические данные.
- **Часть преподавателей без кафедры** (пустой `kafedra` в `data/teachers.json`) — они находятся поиском и имеют расписание, но не попадают в группировку по кафедрам.
- **Модалка выбора** ограничена по высоте в `vh` (единицы большого вьюпорта): на телефонах с динамическими панелями браузера (iOS Safari) низ карточки может уходить под панель, тогда прокручивается подложка. Переход на `dvh`/`svh` — в планах.
- **Старые зеркала заморожены** — см. блок «Про старые адреса» в начале.

## Стек

Один `index.html`: HTML + CSS (CSS-переменные тем, стеклянные слои, `backdrop-filter`, keyframes) + vanilla JS без зависимостей и сборщика. Инструменты: Python 3.12 (только stdlib) для сбора данных, Node.js + jsdom для рендер-теста.
