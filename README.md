# Расписание БарГУ

Расписание занятий **всех групп и преподавателей Барановичского государственного университета (БарГУ)** — одностраничный сайт в стиле Material UI с данными официального [rasp.barsu.by](https://rasp.barsu.by/stud.php).

**🔗 Сайт:** https://zxkittenxd.github.io/barsu-schedule/

Неофициальный студенческий проект. Без бэкенда и без сборки — чистые HTML/CSS/JS, а расписание автоматически собирает GitHub Actions.

---

## Возможности

- **134 группы**, 5 факультетов: инженерный, экономики и права, педагогики и психологии, лингвистический, ИПКиП
- **249 преподавателей**, 15 кафедр: карточки пар с группами, аудиториями и заменами; клик по группе в карточке открывает её расписание
- **Два режима** — «Группы» и «Преподаватели»: переключатель под выбором группы, пункт меню, hash-ссылки `#ПИТТ21/2026-10-19/ПН` и `#t/Фамилия И.О./2026-10-19/ПН`
- **Выбор группы / преподавателя** — модалка с поиском (понимает коды с дефисом и без: «ПИТТ-21» = «ПИТТ21») и вкладками факультетов / кафедр
- **Неделя ПН–СБ**, переключение дней сегмент-контролом, в т.ч. перетаскиванием (drag) на тач-устройствах
- **Автообновление**: GitHub Actions каждые 3 часа собирает rasp.barsu.by и публикует свежий JSON; открытая вкладка подхватывает новый снимок сама (раз в 5 минут и при возврате на страницу)
- **Официальный фрейм** с rasp.barsu.by — эталон «как есть» со всеми заменами; в режиме преподавателей форма уходит в `teach.php`
- **Material UI**: светлая и тёмная темы, акцентные цвета, поддержка `prefers-reduced-motion`
- **Мобильная адаптация**: компактный топбар, полноэкранная модалка выбора, drag-слайдер дней
- Кэш в `localStorage` как аварийная копия: просмотренные расписания открываются даже без сети

## Структура репозитория

```
├── index.html                     # приложение (CSS + разметка + JS) и BOOT-снимок данных
├── data/
│   ├── g000.json … g133.json      # по файлу на группу, грузятся лениво по клику
│   ├── p000.json … p248.json      # по файлу на преподавателя
│   ├── teachers.json              # каталог преподавателей: имя → кафедра → файл
│   └── version.json               # метка свежести: по ней вкладка понимает, что вышел новый снимок
├── tools/
│   ├── scrape.py                  # сбор rasp.barsu.by -> data/*.json + BOOT (только stdlib)
│   └── smoke-test.js              # рендер-тест страницы в jsdom перед публикацией
└── .github/workflows/
    └── update-schedule.yml        # cron: собрать данные, проверить, закоммитить
```

## Как работают данные

1. **Сбор групп.** `tools/scrape.py` делает GET `rasp.barsu.by/stud.php` (каталог групп и список недель), затем POST на каждую группу и неделю и парсит HTML-таблицы. Тянутся текущая и следующая неделя (там бывают замены) плюс незаполненные недели за последние 21 день. Прошлые недели университет уже не правит, поэтому пустой ответ запоминается в `meta.probed` и повторно не запрашивается (~270 запросов, ~45 с на прогон).
2. **Преподаватели.** Каталог имён и кафедр берётся из `teach.php` одним GET. Текущая неделя каждого преподавателя запрашивается напрямую из официального `teach.php` — его таблица богаче групповой (туда попадают пары вроде курсового проектирования, которых нет в групповых таблицах). Остальные недели строятся бесплатно: транспозицией уже собранных данных групп (в каждой паре группы указан преподаватель). Сверка с официальным `teach.php` на выборке преподавателей дала полное совпадение пар.
3. **Публикация.** Результат пишется в `data/gNNN.json`, `data/pNNN.json`, `data/teachers.json`, в BOOT-снимок внутри `index.html` и в `data/version.json`. Файл перезаписывается только если содержимое реально изменилось — при отсутствии изменений коммита и пересборки Pages нет.
4. **Снимок.** В `index.html` встроен JSON-снимок: список всех групп + расписание группы по умолчанию (ПИТТ21, 6 последних недель). Остальное подгружается по требованию, каталог преподавателей — лениво при первом открытии режима.
5. **Клиент.** Кнопка «обновить» перечитывает `version.json` и JSON текущей сущности с того же домена — это работает всегда и мгновенно. Раз в 5 минут и при возврате на вкладку сайт сам проверяет `version.json` и подхватывает новый снимок без перезагрузки.
6. Форматы: `data/gNNN.json` — `meta` (группа, факультет, специальность, `fetchedAt`, доступные недели, `probed`) + `schedules` (недели → дни → пары → занятия с типом, преподавателем, аудиторией, подгруппой); `data/pNNN.json` — то же, но в паре вместо преподавателя указаны группы.

> **Почему не «живой запрос из браузера».** `rasp.barsu.by` не отдаёт CORS-заголовки и принимает параметры только в POST, поэтому браузер не может запросить его напрямую. Обход через публичные CORS-реле не сработал: allorigins и codetabs не пробрасывают POST-тело, corsproxy.io требует ключ (401), cors.lol отдаёт 429, corsfix — 403. Сбор на стороне сервера решает проблему надёжно и без сторонних сервисов.

## Локальный запуск

`fetch()` не работает с `file://`, поэтому нужен любой статический сервер:

```bash
git clone https://github.com/zxkittenxd/barsu-schedule.git
cd barsu-schedule
python3 -m http.server 8080
# открыть http://localhost:8080
```

Ручной прогон сборщика:

```bash
python3 tools/scrape.py --dry-run        # отчёт без записи
python3 tools/scrape.py                  # пересобрать data/*.json и BOOT-снимок
python3 tools/scrape.py --only ПИТТ21    # одна группа (отладка)
```

Рендер-тест (нужны Node.js и локальный сервер; проверяет оба режима):

```bash
python3 -m http.server 8099 &
npm install --no-save --prefix /tmp/jsdom jsdom
NODE_PATH=/tmp/jsdom/node_modules node tools/smoke-test.js
# или против публикации:
NODE_PATH=/tmp/jsdom/node_modules node tools/smoke-test.js https://zxkittenxd.github.io/barsu-schedule/
```

## Деплой и автообновление

Сайт опубликован на **GitHub Pages** (ветка `main`, корень): каждый пуш в `main` пересобирает https://zxkittenxd.github.io/barsu-schedule/.

Workflow **`Обновление расписания`** (`.github/workflows/update-schedule.yml`):

- **когда:** cron `10 */3 * * *` (UTC) — каждые 3 часа; плюс кнопка *Run workflow* во вкладке Actions и самопроверка после правок `tools/scrape.py`;
- **что делает:** собирает данные → прогоняет рендер-тест в jsdom → коммитит в `main` от встроенного `GITHUB_TOKEN` → Pages пересобирается;
- **если источник недоступен** или сменил вёрстку, скрипт падает, данные не трогает, workflow краснеет (GitHub пришлёт письмо); сайт продолжает показывать последний рабочий снимок;
- **если изменений нет**, коммит не создаётся.

> GitHub отключает cron-воркфлоу в репозиториях без активности 60 дней. Если обновления вдруг встали — нажмите *Run workflow* вручную, это вернёт планировщик к жизни.

Зеркало: https://pitt21-rasp.surge.sh (Surge.sh, обновляется вручную — может отставать от Pages).

## Дисклеймер

Проект не связан с Барановичским государственным университетом. Все данные принадлежат университету и берутся из открытых источников rasp.barsu.by (`stud.php`, `teach.php`). При расхождении расписания приоритет у официального сайта.
