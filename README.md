# Расписание БарГУ

Расписание занятий **всех групп Барановичского государственного университета (БарГУ)** — одностраничный сайт в стиле Material UI с данными официального [rasp.barsu.by](https://rasp.barsu.by/stud.php).

**🔗 Сайт:** https://zxkittenxd.github.io/barsu-schedule/

Неофициальный студенческий проект. Без бэкенда и без сборки — чистые HTML/CSS/JS, а расписание автоматически собирает GitHub Actions.

---

## Возможности

- **131 группа**, 5 факультетов: инженерный, экономики и права, педагогики и психологии, лингвистический, ИПКиП
- **Выбор группы** — модалка с поиском (понимает коды с дефисом и без: «ПИТТ-21» = «ПИТТ21») и вкладками факультетов
- **Hash-ссылки** вида `#ПИТТ21/2026-10-05/ПН` — можно поделиться конкретной группой, неделей и днём
- **Неделя ПН–СБ**, переключение дней сегмент-контролом, в т.ч. перетаскиванием (drag) на тач-устройствах
- **Автообновление**: GitHub Actions каждые 3 часа собирает rasp.barsu.by и публикует свежий JSON; открытая вкладка подхватывает новый снимок сама (раз в 5 минут и при возврате на страницу)
- **Официальный фрейм** с rasp.barsu.by — всегда доступный эталон «как есть», со всеми заменами
- **Material UI**: карточки с простыми тенями, без тяжёлых backdrop-filter/анимаций, светлая и тёмная темы
- **Мобильная адаптация**: компактный топбар, полноэкранная модалка выбора группы, drag-слайдер дней
- Кэш в `localStorage` как аварийная копия: просмотренные группы открываются даже без сети

## Структура репозитория

```
├── index.html                     # приложение (CSS + разметка + JS) и BOOT-снимок данных
├── data/
│   ├── g000.json … g130.json      # по файлу на группу, грузятся лениво по клику
│   └── version.json               # метка свежести: по ней вкладка понимает, что вышел новый снимок
├── tools/
│   ├── scrape.py                  # сбор rasp.barsu.by -> data/*.json + BOOT (только stdlib)
│   └── smoke-test.js              # рендер-тест страницы в jsdom перед публикацией
└── .github/workflows/
    └── update-schedule.yml        # cron: собрать данные, проверить, закоммитить
```

## Как работают данные

1. **Сбор.** `tools/scrape.py` делает GET `rasp.barsu.by/stud.php` (каталог групп и список недель), затем POST на каждую группу и неделю и парсит HTML-таблицы. Тянутся текущая и следующая неделя (там бывают замены) плюс незаполненные недели за последние 21 день. Прошлые недели университет уже не правит, поэтому пустой ответ запоминается в `meta.probed` и повторно не запрашивается.
2. **Публикация.** Результат пишется в `data/gNNN.json`, в BOOT-снимок внутри `index.html` и в `data/version.json`. Файл перезаписывается только если содержимое реально изменилось — при отсутствии изменений коммита и пересборки Pages нет.
3. **Снимок.** В `index.html` встроен JSON-снимок: список всех групп + расписание группы по умолчанию (ПИТТ21, 6 последних недель). Остальные группы подгружаются из `data/gNNN.json` по требованию.
4. **Клиент.** Кнопка «обновить» перечитывает `version.json` и JSON текущей группы с того же домена — это работает всегда и мгновенно. Раз в 5 минут и при возврате на вкладку сайт сам проверяет `version.json` и подхватывает новый снимок. Если сети нет, показывается копия из `localStorage`. Ниже на странице — iframe с официальным ответом rasp.barsu.by.
5. Формат `data/gNNN.json`: `meta` (группа, факультет, специальность, `fetchedAt`, доступные недели, `probed`) + `schedules` (недели → дни → пары → занятия с типом, преподавателем, аудиторией, подгруппой).

> **Почему не «живой запрос из браузера».** `rasp.barsu.by` не отдаёт CORS-заголовки и принимает параметры только в POST, поэтому браузер не может запросить его напрямую. Обход через публичные CORS-реле не сработал: allorigins и codetabs не пробрасывают POST-тело, corsproxy.io требует ключ (401), cors.lol отдаёт 429, corsfix — 403. Отсюда и «расписание не обновляется» в прежней версии. Сбор на стороне сервера решает проблему надёжно и без сторонних сервисов.

## Локальный запуск

`fetch()` не работает с `file://`, поэтому нужен любой статический сервер:

```bash
git clone https://github.com/zxkittenxd/barsu-schedule.git
cd barsu-schedule
python3 -m http.server 8080
# открыть http://localhost:8080
```

## Деплой

Сайт опубликован на **GitHub Pages** (ветка `main`, корень): каждый пуш в `main` автоматически пересобирает https://zxkittenxd.github.io/barsu-schedule/.

### Автообновление расписания

Workflow **`Обновление расписания`** (`.github/workflows/update-schedule.yml`):

- **когда:** cron `10 */3 * * *` (UTC), то есть каждые 3 часа; плюс ручной запуск кнопкой *Run workflow* во вкладке Actions и самопроверка после правок `tools/scrape.py`;
- **что делает:** собирает данные → прогоняет рендер-тест страницы в jsdom → коммитит в `main` → GitHub Pages пересобирает сайт;
- **если rasp.barsu.by недоступен** или сменил вёрстку, скрипт падает, данные не трогает, а workflow краснеет (GitHub пришлёт письмо). Сайт при этом продолжает показывать последний рабочий снимок;
- **если изменений нет**, коммит не создаётся.

Ручной прогон локально:

```bash
python3 tools/scrape.py --dry-run        # посмотреть отчёт, ничего не записывая
python3 tools/scrape.py                  # пересобрать data/*.json и BOOT-снимок
python3 tools/scrape.py --only ПИТТ21    # одна группа (отладка)
```

Рендер-тест (нужны Node.js и локальный сервер):

```bash
python3 -m http.server 8099 &
npm install --no-save --prefix /tmp/jsdom jsdom
NODE_PATH=/tmp/jsdom/node_modules node tools/smoke-test.js
```

Зеркало: https://pitt21-rasp.surge.sh (Surge.sh, обновляется вручную — может отставать от Pages).

## Дисклеймер

Проект не связан с Барановичским государственным университетом. Все данные принадлежат университету и берутся из открытого источника rasp.barsu.by. При расхождении расписания приоритет у официального сайта.
